Notes:
- **Generated code is checked in** (`apigen/`, `db/gen/`, `dashboard/src/api/schema.d.ts`). CI runs generators and fails on diff. Rationale: `git clone && go build` must work without toolchain setup.
- `runtime/` is an internal package now; the vision doc's top-level `runtime/` repo materializes at extraction time (Phase 3+), not before.
- The built SPA is embedded into the Go binary at image-build time by copying `dashboard/dist/` → `api/internal/webdist/static/`. In dev, the Vite server proxies to the API instead (see [`09-frontend.md`](09-frontend.md)).

## Makefile targets

The Makefile is the automation entrypoint for humans, CI, and agents. Every target is non-interactive. Required targets:

| Target | Does |
|---|---|
| `make setup` | Install pinned tool versions (oapi-codegen, sqlc, goose, golangci-lint) via `go install`; `npm ci` in dashboard |
| `make dev` | `docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d postgres redis minio`, then prints next steps |
| `make dev-api` | Run the API locally against dev services (`go run ./cmd/platform serve`) with `.env` loaded |
| `make dev-web` | `npm run dev` in dashboard (Vite on :5173, proxying `/api` → :8080) |
| `make generate` | oapi-codegen + sqlc + `npm run generate:api` (TS types from openapi.yaml) |
| `make lint` | `golangci-lint run` + `npm run lint` + `npm run typecheck` + OpenAPI lint (`vacuum lint`) |
| `make test` | Go unit tests (`go test ./... -short`) + `npm test` |
| `make test-integration` | `go test ./... -run Integration` — testcontainers spins up PG/Redis/MinIO |
| `make build` | Build dashboard, copy dist into `webdist/static`, `go build` the binary |
| `make image` | `docker build` the production image |
| `make smoke` | `docker compose up -d --build` + `scripts/smoke.sh` + compose down |
| `make migrate-new name=<slug>` | Create a new empty goose migration |
| `make seed` | Run `platform seed` against the dev database |

## AGENTS.md — required content

`AGENTS.md` at the repo root is a first-class artifact, updated in the same PR as any change that invalidates it. Required sections:

1. **What this is** — two sentences + link to `docs/`.
2. **Setup** — exact commands from clean clone to running dev environment (`make setup && make dev && make dev-api` + `make dev-web`), with expected output snippets and the three URLs (API :8080, web :5173, MinIO console :9001).
3. **Architecture map** — one paragraph per top-level directory; the package table from [`01-architecture.md`](01-architecture.md) inlined or linked.
4. **Common tasks** — recipes: add an endpoint (spec → generate → handler → service → query → test), add a migration, add a frontend route, run one test, debug a failing container instance.
5. **Conventions** — the hard rules from [`01-architecture.md`](01-architecture.md) and code style from [`03-tech-stack.md`](03-tech-stack.md), abridged.
6. **Gotchas** — anything discovered during development that would trip an agent (e.g. "regenerate after editing openapi.yaml or handlers won't compile").

## Git & code conventions

- **Branches**: `main` is protected; work on `feat/<slug>`, `fix/<slug>`, `docs/<slug>`.
- **Commits**: Conventional Commits (`feat:`, `fix:`, `docs:`, `chore:`, `refactor:`, `test:`). Imperative mood, ≤ 72-char subject.
- **PRs**: must pass CI; PR description states which milestone/feature (e.g. `M4/F5`) it advances.
- **File naming**: Go: package-per-directory, `snake_case.go` files, `_test.go` beside code. TS: `kebab-case.ts(x)` files, `PascalCase` component names.
- **No TODO comments** — file an issue or fix it. `FIXME` fails lint.
